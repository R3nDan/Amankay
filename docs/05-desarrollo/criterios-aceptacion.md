# Criterios de aceptación del MVP

Criterios observables alineados con las decisiones aprobadas en el SRS y el MER. Sirven de base para validar los flujos; no sustituyen las pruebas técnicas. Los puntos indicados **pendientes** corresponden a datos de entorno o evaluación académica, no reabren reglas funcionales aprobadas.

| Área | Criterio de aceptación observable |
| --- | --- |
| Acceso y permisos | El personal opera según su rol y sucursales asignadas; el repartidor solo consulta y actualiza sus entregas. Clientes consultan catálogo sin sesión; para pedir en mesa requieren una sesión QR vigente. |
| Productos | Una persona administradora autorizada puede crear/editar/desactivar producto y precio global; producto desactivado no aparece como disponible para nuevos pedidos. |
| Inventario | Una aceptación descuenta una vez las cantidades pedidas en la sucursal responsable; si no hay stock suficiente, no deja saldo negativo ni pedido aceptado. Personal autorizado de inventario registra existencias iniciales, ajustes y mermas con motivo obligatorio. Los movimientos originales permanecen inmutables; cada uno puede tener como máximo una compensación total, sin cadenas. |
| Recogida | Si la sede elegida no puede completar el carrito, el cliente ve los productos que faltan y una recomendación que sí cubre el carrito completo; no se genera un pedido incompleto silenciosamente. |
| Domicilio | GPS es opcional y requiere consentimiento. Sin GPS se solicitan dirección y barrio para asignación manual. Una sola sede debe completar el pedido; si ninguna puede, se rechaza. La cobertura aprobada es Neiva y la tarifa es 2.000 COP; validar automáticamente el límite geográfico requiere configurar el polígono/criterio y las coordenadas reales de las sedes. |
| Pedido externo | Un pedido puede aceptarse/rechazarse por personal; cliente puede consultar estado e historial con un código impredecible. La página pública no muestra dirección completa ni teléfono. |
| WhatsApp | Desde un enlace se abre conversación con el negocio; no se usa API. Personal registra manualmente el pedido en el panel y luego sigue el flujo común. |
| Pedido QR | QR identifica sucursal y mesa; sin sesión activa no permite enviar pedido. El personal inicia/cierra sesión; al cierre se invalida el acceso. Varios dispositivos pueden pedir durante sesión. |
| Cuenta de mesa | Varios pedidos aceptados de la sesión se reflejan en una cuenta derivada de dichos pedidos; no existe entidad `DetalleCuenta`. Cerrar la sesión invalida el token QR; la cuenta se cierra por separado y bloquea otra sesión mientras permanezca abierta. La expiración configurable del token es de ocho horas y no cierra la cuenta. |
| Pagos | Transferencia requiere comprobante y verificación manual; efectivo se registra desde el panel. Cada intento cubre el saldo pendiente completo; se conservan los reintentos, no se permite pago parcial ni sobrepago, y un pago se vincula a pedido externo o cuenta de mesa, nunca a ambos. El reembolso manual es exclusivamente total. |
| Cancelaciones | El cliente puede solicitar cancelación antes de iniciar preparación. Personal autorizado de atención decide aprobarla o rechazarla; si se aprueba, se restaura inventario solo cuando había sido descontado y las unidades son recuperables. |
| Repartos | Atención asigna manualmente un repartidor; solo este accede y actualiza la entrega asignada, sin saltar la transición de recogida. El repartidor registra la incidencia de una entrega fallida; personal autorizado de operaciones decide los reintentos y su resolución. La inspección formal de devoluciones queda fuera del MVP y un retorno físico no se reincorpora automáticamente al inventario. |
| Recaudo de entrega | El repartidor declara el efectivo de una entrega completada; personal autorizado registra lo recibido. La diferencia requiere motivo. Una rectificación autorizada conserva el antes/después en auditoría y no elimina el registro original. |
| Reposición | Sucursal secundaria solicita; principal revisa y despacha; secundaria registra recepción y diferencias. Se permiten múltiples despachos y recepciones parciales por solicitud, sin límite funcional fijo; cada recepción referencia el despacho concreto. |
| Administración | Horarios configurables por sede; catálogo y precios globales; la configuración general de domicilio aplica la cobertura inicial Neiva y tarifa configurable de 2.000 COP; la sucursal se asigna por disponibilidad del pedido completo y proximidad. Reportes muestran ventas, pedidos, inventario y reposiciones; no productos más vendidos. |
| Usabilidad | Representantes de roles completan tareas principales sin asistencia y valoran facilidad de uso. El protocolo, la muestra, las tareas, la escala y el umbral de éxito siguen pendientes en P-18. |

La carga de catálogo definitivo, saldos iniciales, coordenadas y límite geográfico se valida cuando el negocio aporte esos datos. Las pruebas de integración con PostgreSQL requieren un destino de prueba expresamente configurado y autorizado.
